These are the only current candidates for narrow changes, in priority order.
Each should first be attempted through configuration or an upstream update.

1. **Test CP2 without sequence packing.** TE's rejection matrix is now known and is specific to the packed training path on `sm103`; changing the layout through supported configuration is the narrowest remaining option.
2. **Make launcher GPU autodetection consume one normalized Slurm GPU count.** This is isolated launcher code and removes dependence on an explicit masking override.
3. **Correct the existing-tensor conversion at its owning call site.** Do this only after a test establishes whether reuse, `as_tensor()`, or `clone().detach()` is semantically correct.

The compiled-DAG timeout is no longer a fix candidate: the launcher-level 1210-second
setting was validated without changing Ray or vLLM.

Everything else should currently be handled by configuration, dependency pin
alignment, an upstream update, monitoring, or explicit acceptance as expected
behavior.
